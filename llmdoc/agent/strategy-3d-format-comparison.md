# Strategy: 3D 模型格式对比分析

## 业务背景

**公司类型:** AI 3D 大模型公司
**当前方案:** glTF + MeshOpt
**目标方案:** USD + Draco

**核心需求:**
1. 安全性 - 模型资产保护
2. 格式统一 - 减少转换损耗
3. DCC/引擎桥接 - 与 Maya/Blender/Unity/Unreal 互通

## 目标

对比以下 3D 模型格式的优缺点：
1. FBX
2. glTF
3. glTF + MeshOpt
4. USDZ
5. USDZ + Draco (USDC 方案)
6. USDZ + Draco (USDA 方案，前端友好)

## 对比维度

| 维度 | 说明 |
|:---|:---|
| 四边面支持 | 是否能表示 Quad (N-gon) |
| DCC 软件支持 | Maya, Blender, 3ds Max, Cinema 4D, Houdini |
| 游戏引擎支持 | Unity, Unreal, Godot |
| Web 支持 | Three.js, Babylon.js, 浏览器原生 |
| 压缩率 | 文件大小优化 |
| 动画支持 | 骨骼、变形、关键帧 |
| 材质系统 | PBR、自定义 Shader |

## 格式详解

### 1. FBX (Filmbox)

| 属性 | 值 |
|:---|:---|
| 开发商 | Autodesk (闭源) |
| 文件类型 | 二进制 / ASCII |
| 四边面 | ✅ 支持 N-gon |
| 压缩 | ❌ 无内置压缩 |

**DCC 支持:**
| 软件 | 支持度 |
|:---|:---|
| Maya | ✅ 原生 (Autodesk) |
| 3ds Max | ✅ 原生 (Autodesk) |
| Blender | ⚠️ 插件 (有限) |
| Cinema 4D | ✅ 良好 |
| Houdini | ✅ 良好 |

**引擎支持:**
| 引擎 | 支持度 |
|:---|:---|
| Unity | ✅ 原生导入 |
| Unreal | ✅ 原生导入 |
| Godot | ✅ 支持 |
| Web | ❌ 不支持 |

**优点:**
- 行业标准交换格式
- 完整的动画支持 (骨骼、BlendShape、约束)
- 保留 N-gon 拓扑

**缺点:**
- 闭源格式，规范不公开
- 文件体积大
- Web 不友好
- Blender 支持有限

### 2. glTF (GL Transmission Format)

| 属性 | 值 |
|:---|:---|
| 开发商 | Khronos Group (开源) |
| 文件类型 | .gltf (JSON) + .bin / .glb (二进制) |
| 四边面 | ❌ 仅三角面 |
| 压缩 | ⚠️ 需扩展 |

**DCC 支持:**
| 软件 | 支持度 |
|:---|:---|
| Maya | ⚠️ 插件 |
| 3ds Max | ⚠️ 插件 |
| Blender | ✅ 原生 |
| Cinema 4D | ⚠️ 插件 |
| Houdini | ⚠️ 插件 |

**引擎支持:**
| 引擎 | 支持度 |
|:---|:---|
| Unity | ⚠️ 插件 (GLTFast) |
| Unreal | ⚠️ 插件 |
| Godot | ✅ 原生 |
| Web | ✅ 最佳支持 |

**优点:**
- 开放标准，规范公开
- Web 原生支持 (WebGL/WebGPU)
- 文件体积小
- PBR 材质标准化

**缺点:**
- 仅支持三角面
- DCC 软件需要插件
- 动画功能有限 (无约束、无 IK)

---

### 3. glTF + MeshOpt

| 属性 | 值 |
|:---|:---|
| 基础格式 | glTF 2.0 |
| 压缩扩展 | EXT_meshopt_compression |
| 压缩率 | 60%-80% |
| 四边面 | ❌ 仅三角面 |

**压缩特性:**
```
原始 glTF:     10 MB
+ MeshOpt:     2-4 MB (60%-80% 压缩)
```

**优点:**
- 快速解码 (GPU 友好)
- 流式加载支持
- 广泛的 Web 库支持

**缺点:**
- 压缩率不如 Draco
- 仍然仅支持三角面

---

### 4. USDZ (Universal Scene Description Zip)

| 属性 | 值 |
|:---|:---|
| 开发商 | Pixar / Apple |
| 文件类型 | ZIP 归档 (.usdc + 纹理) |
| 四边面 | ✅ 支持 N-gon |
| 压缩 | ❌ 无 mesh 压缩 |

**DCC 支持:**
| 软件 | 支持度 |
|:---|:---|
| Maya | ✅ 原生 (USD 插件) |
| 3ds Max | ⚠️ 插件 |
| Blender | ✅ 原生 (3.0+) |
| Cinema 4D | ⚠️ 有限 |
| Houdini | ✅ 原生 (Solaris) |

**引擎支持:**
| 引擎 | 支持度 |
|:---|:---|
| Unity | ⚠️ 插件 |
| Unreal | ✅ 原生 (5.0+) |
| Godot | ❌ 不支持 |
| Web | ⚠️ 有限 (model-viewer) |
| iOS AR | ✅ 原生 |

**优点:**
- 支持 N-gon 拓扑
- Apple AR 生态原生支持
- 完整的场景描述能力
- 支持变体 (Variants)

**缺点:**
- 文件体积大
- Web 支持有限
- 生态系统较新

---

### 5. USDZ + Draco (USDC 方案)

| 属性 | 值 |
|:---|:---|
| 基础格式 | USDC (Crate 二进制) |
| 压缩 | Draco (.drc 外部文件) |
| 压缩率 | **91%-94%** |
| 四边面 | ⚠️ 取决于 `preserve_polygons` 参数 |

**关于四边面保留:**

Draco **不会默认转为三角面**。是否保留多边形由 `preserve_polygons` 参数控制：

| 参数值 | 行为 |
|:---|:---|
| `-1` | 不保留多边形 (转为三角面) |
| `0` | 自动检测 |
| `1` | 保留多边形 (N-gon) |

当前脚本 [`draco_compress_safe.py`](../../draco_compress_safe.py:25) 使用 `preserve_polygons = -1`，所以**会转为三角面**。

如需保留四边面，修改为：
```python
self.preserve_polygons = 1
```

**文件结构:**
```
model.usdc           # USD 场景描述
model.usdc.draco/    # Draco 压缩数据
├── mesh_0.drc
├── mesh_1.drc
└── ...
```

**优点:**
- 极高压缩率 (91%-94%)
- 二进制格式，解析快
- 保留 USD 场景结构

**缺点:**
- 丢失四边面拓扑
- 需要 Draco 解码器
- 非标准 USD 扩展
- 兼容性有限

---

### 6. USDZ + Draco (USDA 方案，前端友好)

| 属性 | 值 |
|:---|:---|
| 基础格式 | USDA (ASCII 文本) |
| 压缩 | Draco (.drc 外部文件) |
| 压缩率 | **91%-94%** |
| 四边面 | ⚠️ 取决于 `preserve_polygons` 参数 (同上) |

**文件结构:**
```
model.usda           # USD 场景描述 (可读文本)
model.usda.draco/    # Draco 压缩数据
├── mesh_0.drc
├── mesh_1.drc
└── ...
```

**优点:**
- 极高压缩率 (91%-94%)
- **前端友好**: USDA 可直接文本解析
- 易于调试和修改
- 无需完整 USD 解析器

**缺点:**
- USDA 文件本身较大 (文本格式)
- 丢失四边面拓扑
- 需要 Draco 解码器
- 非标准 USD 扩展

## 使用场景推荐

### 场景 1: DCC 软件间交换
**推荐:** FBX
- 保留 N-gon 拓扑
- 完整动画支持

### 场景 2: Web 3D 展示
**推荐:** glTF + MeshOpt
- 最佳浏览器兼容性
- 良好的压缩率

### 场景 3: iOS AR 体验
**推荐:** USDZ
- Apple 原生支持
- 无需额外解码

### 场景 4: 大型模型存储/传输
**推荐:** USDZ + Draco (USDA)
- 最高压缩率
- 前端可解析

### 场景 5: 影视制作流程
**推荐:** USD/USDZ (无压缩)
- 保留完整拓扑
- 支持变体和引用

---

## DO NOTs

- ❌ 不要用 FBX 做 Web 项目
- ❌ 不要用 glTF 保存四边面模型 (会被三角化)
- ❌ 不要假设 Draco 一定会三角化 (可配置 `preserve_polygons`)
- ❌ 不要在生产环境使用非标准 USD 扩展 (如 Draco) 而不做兼容性测试

## 战略评估：glTF+MeshOpt → USD+Draco 迁移

### 需求矩阵分析

| 需求 | glTF+MeshOpt | USD+Draco | 评估 |
|:---|:---:|:---:|:---|
| **安全性** | ⚠️ 中等 | ✅ 更好 | USD 二进制格式更难逆向 |
| **格式统一** | ⚠️ Web优先 | ✅ 全栈 | USD 是影视/游戏/AR 统一标准 |
| **DCC 桥接** | ⚠️ 需插件 | ✅ 原生 | Maya/Houdini 原生支持 USD |
| **引擎支持** | ⚠️ 需插件 | ✅ 趋势 | UE5/Unity 都在加强 USD |
| **压缩率** | 60-80% | 91-94% | Draco 压缩率更高 |
| **Web 支持** | ✅ 最佳 | ⚠️ 有限 | glTF 仍是 Web 首选 |

### 安全性深度分析

| 维度 | glTF | USD |
|:---|:---|:---|
| **格式透明度** | JSON 明文，易读 | 二进制 (USDC)，难读 |
| **逆向难度** | 低 (标准公开) | 中 (需要 USD 库) |
| **加密支持** | ❌ 无原生支持 | ⚠️ 无原生，但可外层加密 |
| **混淆可能** | 低 | 中 (可自定义 Schema) |

**结论:** USD 的安全性略优于 glTF，但两者都不提供真正的 DRM。如需强安全，需要：
- 服务端渲染 (不下发模型)
- 自定义加密层
- 流式传输 + Token 验证

### DCC/引擎桥接深度分析

#### DCC 软件支持对比

| 软件 | glTF | USD | 备注 |
|:---|:---:|:---:|:---|
| **Maya** | 插件 | ✅ 原生 | Autodesk 全面支持 USD |
| **Blender** | ✅ 原生 | ✅ 原生 | 3.0+ 两者都支持 |
| **3ds Max** | 插件 | ⚠️ 插件 | USD 支持在改进中 |
| **Houdini** | 插件 | ✅ 原生 | Solaris 是 USD 原生 |
| **Cinema 4D** | 插件 | ⚠️ 有限 | 两者都需要插件 |

#### 游戏引擎支持对比

| 引擎 | glTF | USD | 趋势 |
|:---|:---:|:---:|:---|
| **Unreal 5** | 插件 | ✅ 原生 | Epic 重点投资 USD |
| **Unity** | 插件 (GLTFast) | ⚠️ 插件 | Unity 正在加强 USD |
| **Godot** | ✅ 原生 | ❌ 无 | 短期内不会支持 USD |
| **Omniverse** | ❌ 无 | ✅ 原生 | NVIDIA 的 USD 平台 |

### 迁移价值重新评估

**核心问题:** 如果最终 Web 输出仍然是 glTF，那迁移到 USD 的意义在哪里？

#### 场景 A: 纯 Web 产品 (如在线 3D 展示)

| 维度 | 迁移价值 |
|:---|:---:|
| 安全性提升 | ❌ 无 (最终还是 glTF) |
| 压缩率提升 | ❌ 无 (MeshOpt 已足够) |
| 格式统一 | ❌ 无 (反而多了一层转换) |
| DCC 桥接 | ⚠️ 有限 (但 glTF 也能导入 DCC) |

**结论:** 如果产品主要是 Web，**迁移没有意义**。

#### 场景 B: 多端产品 (Web + iOS AR + 游戏引擎)

| 维度 | 迁移价值 |
|:---|:---:|
| iOS AR | ✅ 有 (USDZ 是 Apple 唯一选择) |
| UE5 集成 | ✅ 有 (USD 原生支持) |
| 格式统一 | ✅ 有 (一个源，多个输出) |
| 场景组合 | ✅ 有 (USD 的变体/引用能力) |

**结论:** 如果需要多端输出，**迁移有意义**。

#### 场景 C: 影视/高端制作流程

| 维度 | 迁移价值 |
|:---|:---:|
| DCC 互通 | ✅ 强 (Maya/Houdini 原生) |
| 场景管理 | ✅ 强 (USD 的核心优势) |
| 渲染集成 | ✅ 强 (Hydra 渲染架构) |

**结论:** 如果目标是影视流程，**迁移非常有意义**。

---

### 诚实的最终建议

| 你的情况 | 建议 |
|:---|:---|
| **主要做 Web 3D** | ❌ **不要迁移**，glTF+MeshOpt 已经是最优解 |
| **需要 iOS AR** | ✅ 迁移有意义，USDZ 是必须的 |
| **需要 UE5/Unity 深度集成** | ⚠️ 可以考虑，但 glTF 也能导入 |
| **需要场景组合/变体** | ✅ 迁移有意义，这是 USD 的核心优势 |
| **需要与影视流程对接** | ✅ 迁移非常有意义 |

### 关于"安全性"的真相

| 误解 | 真相 |
|:---|:---|
| "USD 二进制更安全" | ❌ 只是稍微难读，不是真正的安全 |
| "Draco 压缩能保护模型" | ❌ Draco 是压缩不是加密 |
| "格式转换能防止盗用" | ❌ 任何能渲染的格式都能被提取 |

**真正的安全方案:**
1. 服务端渲染 (不下发模型)
2. 流式传输 + Token 验证
3. 法律手段 (版权/专利)

### 最终结论

**如果你的产品主要是 Web 3D，且没有 iOS AR / 影视流程 / 场景组合的需求：**

> ❌ **迁移到 USD+Draco 没有实际意义**
>
> 你会增加：
> - 工具链复杂度
> - 转换损耗
> - 维护成本
>
> 你不会获得：
> - 更好的安全性
> - 更好的 Web 性能
> - 更好的压缩率 (MeshOpt 60-80% vs Draco 91-94%，但 Web 加载 MeshOpt 更快)

**建议:** 保持 glTF+MeshOpt，除非有明确的多端输出需求。

## 针对你的场景：DCC 编辑 + Web 展示

### 场景分析

```
AI 3D 大模型
     │
     ▼
  [中间格式] ──────────────────┐
     │                        │
     ▼                        ▼
Maya/Blender 编辑         Web 展示
```

### 关键问题：glTF 能否满足 DCC 导入需求？

| DCC 软件 | glTF 导入 | 体验 |
|:---|:---:|:---|
| **Blender** | ✅ 原生 | 非常好，无需插件 |
| **Maya** | ⚠️ 插件 | 需要安装 glTF 插件，但可用 |
| **3ds Max** | ⚠️ 插件 | 需要安装插件 |
| **Cinema 4D** | ⚠️ 插件 | 需要安装插件 |

**结论:** glTF 已经可以导入主流 DCC 软件，只是 Maya 需要插件。

### 对比：glTF vs USD 在 DCC 导入场景

| 维度 | glTF | USD |
|:---|:---|:---|
| **Blender 导入** | ✅ 原生 | ✅ 原生 (3.0+) |
| **Maya 导入** | ⚠️ 插件 | ✅ 原生 |
| **导入后编辑** | ✅ 正常 | ✅ 正常 |
| **四边面保留** | ❌ 无 | ✅ 有 |
| **动画保留** | ✅ 基础 | ✅ 完整 |
| **材质保留** | ✅ PBR | ✅ PBR + 更多 |

### 迁移到 USD 的真正价值点

对于"DCC 编辑 + Web 展示"场景：

| 价值点 | 重要性 | 说明 |
|:---|:---:|:---|
| **Maya 原生支持** | ⭐⭐ | 不用装插件，但插件也能用 |
| **四边面保留** | ⭐⭐⭐ | **这是关键！** AI 生成的模型如果有四边面，glTF 会三角化 |
| **更好的动画** | ⭐ | 如果 AI 不生成动画，无意义 |
| **场景组合** | ⭐ | 如果只是单个模型，无意义 |

### 核心问题：你的 AI 模型有四边面吗？

| AI 模型类型 | 四边面 | 建议 |
|:---|:---:|:---|
| **NeRF/3DGS 重建** | ❌ 无 (点云/三角面) | glTF 足够 |
| **传统 Mesh 生成** | ❌ 通常三角面 | glTF 足够 |
| **拓扑优化后的模型** | ✅ 可能有 | USD 有价值 |
| **需要后续细分建模** | ✅ 需要 | USD 有价值 |

### 针对 DCC+Web 场景的最终建议

**如果你的 AI 生成的是三角面模型（大多数 AI 3D 模型都是）：**

> ❌ **迁移到 USD 没有意义**
>
> 因为：
> - glTF 已经可以导入 Maya/Blender（Maya 需要插件，但很成熟）
> - 三角面模型用 glTF 和 USD 没有区别
> - Web 展示 glTF 更好
> - 你会增加工具链复杂度，但不会获得任何实际好处

**如果你的 AI 生成的是四边面模型，且用户需要在 DCC 中做细分建模：**

> ✅ **迁移到 USD 有意义**
>
> 因为：
> - USD 能保留四边面拓扑
> - Maya 原生支持更好
> - 但 Web 输出仍需转 glTF

### 推荐架构（如果确实需要迁移）

```
AI 3D 大模型
     │
     ▼
   USD (内部存储，保留四边面)
     │
     ├──────────────────┐
     ▼                  ▼
  DCC 下载           Web 展示
  (USD/FBX)         (glTF+MeshOpt)
```

**注意:** 即使用 USD 作为内部格式，Web 展示仍然建议用 glTF。

### 一句话总结

> **如果你的 AI 模型是三角面（99% 的情况），迁移到 USD 没有任何实际意义。**
>
> glTF 已经能满足 DCC 导入 + Web 展示的需求。
